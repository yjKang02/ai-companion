# 저장소와 리뷰 운영

기존 대화에서 제안한 저장소 관리 방침을 초기 환경 설정에 반영한다. 이 문서는 운영 방법이며 작업 상태·목표일은 [프로젝트 문서](프로젝트.md)가 원본이다.

## 저장소 이름

사용자가 [yjKang02/ai-companion](https://github.com/yjKang02/ai-companion)을 생성했다. 메신저·모델 교체 방향을 드러내고 특정 공급자 이름에 종속되지 않는 이름이다. GitHub 설명 문구는 다음을 제안한다.

> 메신저와 모델을 교체할 수 있는 개인용 AI Companion. Python 기반으로 Discord와 LM Studio부터 지원합니다.

나중에 제품 이름이 정해지면 변경할 수 있다. GitHub는 이름 변경에 리다이렉트를 제공하지만 로컬 origin과 배지·외부 연동은 새 주소로 정리한다. 지금부터 이름 변경을 전제로 운영할 필요는 없다. [GitHub 이름 변경 안내](https://docs.github.com/en/repositories/creating-and-managing-repositories/renaming-a-repository)

## 자동 검사

[CI](../.github/workflows/ci.yml)는 `main` push, `main` 대상 PR, 수동 실행에 반응한다. Ubuntu 3.11·3.13, Windows 3.13에서 설치와 검증을 수행하고 Ruff·mypy는 Ubuntu 3.13에서 한 번 실행한다. init 커밋은 빈 패키지 import, 기능 PR은 pytest를 실행한다. 기능 브랜치가 앞으로 테스트를 지워 검사를 우회하지 않도록 테스트 실패를 숨기는 조건문이나 `continue-on-error`를 두지 않는다.

GitHub 호스팅 runner를 사용하고 토큰 권한은 contents: read로 제한한다. 실제 Discord 토큰이나 LM Studio 서버를 CI에 제공하지 않는다. 현재 호환 범위 의존성을 설치하므로 완전한 버전 고정은 아니며, 재현 가능한 배포가 필요해지면 lock 파일을 별도 검토한다. [Python CI](https://docs.github.com/en/actions/tutorials/build-and-test-code/python)

[Dependabot](../.github/dependabot.yml)은 pip·GitHub Actions를 매주 확인하도록 설정했다. Python minor/patch는 묶고 major는 별도로 검토한다. 업데이트는 자동 병합하지 않는다. 봇이 생성하는 제목·본문은 한국어를 보장하지 않으므로 최종 squash 제목과 상세 본문을 한국어로 정리한다. [Dependabot](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference)

## CodeRabbit

[설정 파일](../.coderabbit.yaml)은 한국어, chill, 경로별 지침을 사용한다. 승인 자동화는 끄고 준비된 PR에 자동 리뷰를 요청한다. draft PR은 기본 제외하므로 준비되면 ready for review로 바꾼다. 스타일은 Ruff에 맡기고 데이터 격리·어댑터 경계·취소·timeout·오류·비밀 정보와 문서의 실제 상태에 집중한다. [설정 문서](https://docs.coderabbit.ai/reference/configuration)

파일 추가만으로 GitHub App이 설치되지는 않는다. GitHub 저장소를 만든 후 CodeRabbit App의 접근 대상을 이 저장소로 선택해야 한다. 이 로컬 작업에서 CodeRabbit 원격 리뷰를 실행했다고 주장하지 않는다.

## GitHub에 적용할 설정

원격 저장소에서 다음 설정을 권장한다. CI·Dependabot은 파일을 기본 브랜치에 올리면 GitHub가 처리한다. CodeRabbit App 설치는 별도이며 파일만으로 완료되지 않는다.

- `main`을 기본 브랜치로 지정하고 PR을 통해 병합한다.
- squash merge를 사용한다. 기능 브랜치의 리뷰와 CI 결과를 확인한 뒤 직접 병합한다.
- main 강제 push와 삭제를 막고 required status checks를 설정한다. 실제 CI 첫 실행 뒤 생성된 체크 이름을 선택한다: `quality`, `test (ubuntu-latest, py3.11)`, `test (ubuntu-latest, py3.13)`, `test (windows-latest, py3.13)`.
- 혼자 개발할 때 사람 승인 1명이나 CodeRabbit 승인을 필수 조건으로 넣지 않는다. 리뷰 대화 해결은 확인한다.
- CodeQL·릴리스 자동화는 공개 범위와 배포 방식이 정해진 뒤 검토한다. Issues를 작업 원본으로 채택하기 전까지 docs의 체크리스트를 복제하지 않는다.

보호 규칙 제공 범위는 공개 여부와 요금제에 따라 확인한다. [Rulesets](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/about-rulesets)

## 최초 업로드 순서

origin은 `https://github.com/yjKang02/ai-companion.git`으로 연결한다. main을 먼저 push한 뒤 feature를 push하고 feature → main PR을 연다. backup은 로컬 보존으로 충분하며 별도 필요가 있을 때만 명시적으로 push한다. `git push --all`로 백업까지 일괄 업로드하지 않는다.

```powershell
git log --oneline --graph --decorate --all
git diff main...feature/discord-lmstudio-connection --stat
```

GitHub 설정과 검사 실행 결과는 실제 원격 응답으로 확인한다. PR을 만들더라도 사용자 리뷰 전에는 병합하지 않는다.
