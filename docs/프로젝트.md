## 목표와 범위

짧은 일상 대화를 이어 가는 개인용 AI Companion을 만든다. 메신저와 모델이 바뀌어도 대화·페르소나·개인 데이터 관리 로직을 재사용할 수 있는 객체지향 구조를 목표로 한다. 사용자가 현재 적용되는 페르소나와 저장된 개인 데이터를 직접 확인하고 수정·삭제할 수 있어야 한다.

원문에서 짧은 응답, 대화 연속성, local-first 방향을 가져온다. 원문의 컴포넌트 구성과 기술 스택은 참고 자료로 취급한다. 이번 요청에 따라 수동 데이터 관리 화면을 MVP로 앞당기고, 자동 기억 추출·관계 시뮬레이션·선제 메시지는 후속 검증으로 둔다.

### 최소 MVP의 제품 범위

| 영역 | MVP에 포함 | 이후 검토 |
| --- | --- | --- |
| 대화 채널 | 허용된 사용자 1명의 Discord DM, 텍스트 대화 | 다른 메신저, 서버 채널, 여러 사용자 |
| 모델 | 로컬 LLM과 외부 API를 같은 포트로 연결, 설정으로 선택 | 추가 공급자, 자동 라우팅·장애 시 자동 전환 |
| 대화 경험 | 짧은 응답 1개, 최근 대화 보존, 처리 중 표시 | 여러 메시지 분할, 인위적 지연, 선택적 무응답 |
| 페르소나 | 말투·성격·호칭·응답 길이 설정 조회와 수정 | 여러 캐릭터, 관계·기분·가상 일상 |
| 개인 데이터 | 사용자가 직접 등록한 사실 CRUD, 대화 조회·삭제 | 자동 사실·사건·일정 추출, 의미 검색 |
| 관리 화면 | 로컬 웹 화면, 저장 후 다음 요청 반영, 변경 상태 갱신 | 원격 접속, 모바일 최적화, 실시간 푸시 |
| 지속성 | 재시작 후 대화·설정·사실 복구 | 다중 서버, 분산 큐 |

초기 가정은 단일 사용자·단일 Companion·단일 프로세스다. 사용자 요청에 따라 Python·discord.py와 LM Studio로 첫 연결을 구현한다. 현재 개발 환경은 Windows·Python 3.13이며, 실제 운영 서버 OS·GPU·VRAM·RAM·모델 ID는 미정이다. 토큰과 런타임 데이터는 문서에 넣지 않는다.

### MVP 완료 시 확인할 결과

1. 허용한 계정이 Discord DM을 보내면 선택한 모델의 짧은 답변을 받는다. 로컬 LLM과 외부 API 각각에서 같은 대화 흐름을 검증한다.
2. 서버 재시작 후 최근 대화를 이어 가고, 저장한 페르소나와 사용자 사실이 유지된다.
3. 관리 화면에서 페르소나를 바꾸면 저장된 버전과 적용 시점을 확인하고 다음 요청에 새 값이 들어간다.
4. 사용자 사실의 추가·수정·비활성화·삭제가 가능하고, 대화 내용도 조회·삭제할 수 있다.
5. 삭제된 기록은 이후 모델 입력에 포함되지 않는다. 과거 대화에 같은 사실이 남아 있을 수 있으므로 관련 대화 삭제도 선택할 수 있다.
6. 모델 시간 초과, 중복 수신, 데이터 수정 중 생성, 비허용 사용자 접근 시 정해진 동작을 검증한다.

위 항목은 구현 수용 기준이며 실제 검증 결과가 아니다. 자연스러움은 별도 사용자 평가로 판단한다.
