## P2: 타이핑 표시 오류가 대화 전체를 중단한다

위치: [DiscordMessenger.typing](../src/ai_companion/adapters/discord.py), [ConversationService.handle](../src/ai_companion/application/conversation.py).

허용된 DM을 수신한 뒤 Discord의 타이핑 표시 요청만 HTTP 500으로 실패하면, 어댑터가 `DeliveryError`를 발생시킨다. 서비스는 모델 호출 전에 이 오류를 만나 로그만 남기고 반환한다. 따라서 메시지 송신 자체가 가능해도 사용자는 답변이나 오류 안내를 받지 못한다. 이벤트는 이미 중복 처리 집합에 들어갔으므로 같은 입력이 재전달되어도 실행하지 않는다.

discord.py 2.7.1의 `Typing.__aenter__`가 최초 타이핑 HTTP 요청을 await하는 코드를 확인했다. 실제 Discord 연결 없이 해당 컨텍스트 진입을 HTTP 500으로 바꾸고 모델·송신을 정상 fake로 둔 재현 결과는 다음과 같다.

```text
입력: 동일한 허용 DM 이벤트 2회
타이핑 컨텍스트 진입: 1회, HTTP 500
모델 호출: 0회
메시지 송신: 0회
```

수정 제안: 타이핑은 선택적 표시이므로 초기화 실패 때 아무 동작 없는 컨텍스트로 대체하고 생성·송신을 계속한다. 취소는 그대로 전파한다. 컨텍스트 본문에서 발생한 모델·송신 오류까지 삼키지 않도록 타이핑 초기화 실패만 분리해 처리한다. 타이핑 실패 후에도 모델·송신이 각각 한 번 실행되는 회귀 테스트가 필요하다.

## 검증과 남은 확인

Windows·Python 3.13 환경에서 기존 테스트 54개, Ruff 검사·포맷 검사, mypy, pip check가 통과했다. 타입 검사 통과는 위 오류 경로의 동작을 보장하지 않는다. 새 main의 별도 스냅샷은 빈 패키지 wheel 빌드·import·정적 검사를 통과했다. CodeRabbit 설정은 공식 JSON 스키마로 검증했다.

Linux 및 Python 3.11 조합은 로컬에서 실행하지 않았으며 GitHub CI 결과로 확인해야 한다. 실제 Discord 로그인·왕복과 LM Studio 생성은 아직 확인하지 않았다. 메모리 이력·최대 글자 수·큐 초과 시 드롭은 [README](../README.md#첫-연결-버전의-범위)에 명시된 초기 제한으로, 이번 리뷰에서 구현 누락으로 판정하지 않았다.

리뷰 반영과 실제 연결 검증의 작업 상태는 [M02](프로젝트.md#작업-목록)에 유지한다.
