# 첫 조사: 작은 MVP에서 교체 가능성과 데이터 편집을 확보할 수 있는가

- 조사일: 2026-09-13
- 관련 프로젝트: [ai-companion](../프로젝트.md)
- 검증 상태: 자료 조사. 코드 실행·모델 비교·Discord 연결 실험은 수행하지 않았다.

이 문서는 최초 자료 조사 시점의 기록이다. 이후 첫 구현 대상은 사용자 요청으로 LM Studio가 되었으며, 현재 작업 상태는 [프로젝트 문서](../프로젝트.md), 채택 내용은 [결정 기록](../결정/001-Python-LMStudio-초기연결.md)을 따른다.

## 핵심 요약

공식 문서상 Discord DM 수신, Ollama 텍스트 생성과 구조화 출력, SQLite 저장, 작은 웹 편집 화면에 필요한 기반은 확인할 수 있다. 이 프로젝트에는 단일 프로세스와 교체 가능한 외부 포트로 시작하는 안을 제안한다. 공식 문서의 기능 지원은 한국어 대화 품질이나 실제 교체 비용을 증명하지 않으므로 별도 실험이 필요하다.

## 기획에서 확인한 요구

[Notion 원문](https://app.notion.com/p/Discord-AI-Companion-3d535739c636818d8784ca837b2c0a45)의 핵심은 짧은 메시지, 최근·장기 기억, 지속되는 캐릭터, 타이밍, 향후 선제 연락이다. 원문은 Python·Ollama·SQLite와 단계별 확장을 제안한다. 이번 사용자 요청은 이를 참고하되 객체지향으로 다시 설계하고, 페르소나·개인 데이터의 실시간 확인과 커스텀을 추가한다.

원문 조회에서 반환된 마지막 편집 시각은 2026-09-12T08:57:49.373Z였으며, 문서 본문의 조사일은 2026-09-08이다. 원문에 소개된 저장소·상용 기능의 정확성이나 최신성은 이번 기록에서 검증한 사실로 취급하지 않는다.

## 확인한 사실과 설계 해석

| 조사 질문 | 공식 자료에서 확인한 사실 | 이 프로젝트에 대한 제안·한계 |
| --- | --- | --- |
| Discord DM만 먼저 구현할 수 있는가? | Gateway에는 `DIRECT_MESSAGES` intent가 있고 앱과의 DM 내용은 Message Content 제한의 예외다. [Gateway](https://docs.discord.com/developers/events/gateway) | DM 전용·허용 계정으로 시작한다. 서버 채널의 일반 메시지와 동일한 권한 조건이라고 가정하지 않는다. 실제 설치·DM 수신은 미검증 |
| 사용자 활동 정보를 기본 입력으로 쓸 것인가? | discord.py는 회원 상태·활동 추적을 Presence Intent 사용 사례로 설명한다. [Intents](https://discordpy.readthedocs.io/en/stable/intents.html) | 기본 DM 대화에 활동 추적을 의존시키지 않는다. DM에서 활동 정보를 항상 얻을 수 있다는 근거는 확보하지 못함 |
| 모델에 공통 텍스트 계약을 둘 수 있는가? | Ollama `/api/chat`은 model·messages 입력과 메시지·종료 정보·사용량 관련 값을 제공한다. streaming의 기본값은 true다. [Chat API](https://docs.ollama.com/api/chat) | 첫 어댑터는 명시적으로 비스트리밍 텍스트 결과로 정규화한다. 이후 타 공급자의 종료 사유·토큰 계산 차이를 따로 변환 |
| 여러 메시지를 JSON으로 생성할 수 있는가? | Ollama는 JSON schema를 format에 전달하고 출력 검증을 하는 예제를 제공한다. [Structured outputs](https://docs.ollama.com/capabilities/structured-outputs) | 가능성은 확인했지만 JSON 형식만 맞는다고 자연스러운 분할이 보장되지는 않는다. 기본 단일 응답 이후 비교 |
| Python에서 상속 없이 인터페이스를 표현할 수 있는가? | `Protocol`은 구조적 서브타이핑을 위한 기반이다. [Python typing](https://docs.python.org/3/library/typing.html#typing.Protocol) | 메신저·모델·저장소 경계를 Protocol로 표현하는 후보. 런타임 입력 검증이나 의미적 계약 준수는 별도 구현·테스트 필요 |
| 채팅과 편집 화면이 SQLite를 함께 쓸 수 있는가? | WAL은 읽기와 쓰기의 병행을 지원하지만 동시 writer는 하나이고 네트워크 파일시스템에 제약이 있다. [SQLite WAL](https://sqlite.org/wal.html) | 단일 호스트·짧은 트랜잭션 후보. 모델 호출 중 쓰기 잠금을 잡지 않는다. 충돌·busy 처리는 실제 검증 필요 |
| 관리 화면에 독립 SPA가 필요한가? | FastAPI는 Jinja2 템플릿을 통한 HTML 응답 구성을 안내한다. [Templates](https://fastapi.tiangolo.com/advanced/templates/) | 소규모 폼과 polling으로 시작 가능하다는 설계 판단. 이 자료가 인증·실시간 일관성을 자동 제공한다는 뜻은 아님 |

## 선택지 비교

| 쟁점 | 초기 제안 | 미루는 선택지·재검토 조건 |
| --- | --- | --- |
| 애플리케이션 구조 | 단일 프로세스, 도메인·유스케이스·어댑터 분리 | 독립 배포·여러 추론 worker가 실제로 필요할 때 서비스 분리 검토 |
| 객체지향 방식 | 작은 포트, 책임을 가진 객체, 합성 | 깊은 상속·범용 factory·플러그인 검색은 구체 요구가 생길 때 |
| 장기 기억 | 직접 편집하는 사실 저장 | 자동 추출은 잘못된 기억을 승인·교정·삭제할 흐름이 갖춰진 후 |
| 화면 갱신 | 저장 직후 반영 + 2초 polling 제안 | 초 단위 갱신으로 부족한 사용자 경험이 확인되면 SSE/WebSocket 비교 |
| 모델 선택 | 하드웨어에 맞는 후보를 같은 사례로 비교 | 원문의 8B~10B 권장 범위를 필수 조건으로 삼지 않음 |
| 기억 검색 | 활성 수동 사실과 최근 대화 | 메모리 양·검색 실패가 실제 병목이 되면 FTS·벡터 검색 비교 |

이 표는 프로젝트 맥락에서의 설계 해석이며 일반적인 성능 우열이나 확정 채택 결정이 아니다.

## 다음 실험

실행 상태는 [프로젝트 작업 목록](../프로젝트.md#작업-목록)에서만 관리한다.

### R02: 첫 모델 비교

R01에서 OS, GPU·VRAM·RAM, 사용 가능한 추론 런타임을 확인한 뒤 후보를 선정한다. 모델 다운로드 전에 공식 모델 카드에서 라이선스, 지원 언어, 컨텍스트 한도와 파일 크기를 확인한다. 현재는 후보 이름을 확정하지 않는다.

비교는 개인정보 없는 합성 한국어 대화 20개로 시작한다. 인사·짧은 반응 5개, 감정 표현 5개, 앞선 사실 회상 5개, 페르소나 수정·상충하는 정보 5개로 구성한다. 이는 실험 계획이며 아직 사례 실행이나 결과는 없다.

동일한 시스템 지시·입력·출력 제한을 사용하고, 모델 ID·버전·양자화·런타임·하드웨어·샘플링 설정을 기록한다. 가능한 경우 같은 seed를 쓰되 결정성을 가정하지 않는다. 각 사례를 3회 반복하는 안으로 편차를 관찰한다. cold start와 warm 실행을 구분하고 완료 응답 지연의 중앙값·p95, 최대 메모리, 오류를 측정한다.

| 평가 축 | 기록 방법 |
| --- | --- |
| 한국어 자연스러움 | 조사자 수동 평가 1~5점, 어색한 표현 원문과 이유 보존 |
| 짧은 대화 | 응답 글자 수, 장문 발생, 불필요한 질문 여부 |
| 페르소나 유지 | 지정한 호칭·말투·응답 길이 지시 위반 수 |
| 기억 정확성 | 제공한 사실을 바르게 사용했는지, 없는 사실을 만들었는지 구분 |
| 실행 가능성 | 지연·VRAM/RAM·실패·반복 실행 안정성 |

설정 반영은 우선 구성된 입력으로 검증한다. 모델이 특정 문장을 반드시 출력해야만 저장 기능이 정상이라고 판단하지 않는다. 품질 점수는 저장 일관성과 구분해 평가한다. 미측정 결과 칸을 예시 수치로 채우지 않는다.

### R03: 단일 텍스트와 메시지 배열 비교

R02의 같은 사례로 단일 짧은 텍스트와 `messages` 배열 출력을 비교한다. 파싱 실패율, 배열 길이, 분할 위치의 자연스러움, 전체 응답 시간과 반복 표현을 기록한다. 분할의 이점이 확인되면 전송 간격을 별도로 비교해 생성 형식과 지연 효과를 혼동하지 않는다. 검증 전에는 원문의 응답 길이 비율·랜덤 지연 공식을 고정하지 않는다.

### M05 검증을 위한 동시 변경 시나리오

모델 응답을 지연시키는 가짜 어댑터로 생성 중 페르소나 수정, 사실 삭제, 대화 전체 삭제를 각각 실행한다. 오래된 출력이 송신되지 않는지, 이미 전송을 시작한 경우 화면이 적용 경계를 정확히 설명하는지 확인한다. 브라우저 두 개에서 같은 revision을 수정해 충돌 표시도 점검한다.
