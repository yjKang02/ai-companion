## 제품 가설

목표는 가장 똑똑한 챗봇이 아니라 Discord에서 짧은 일상 대화를 나눌 때 덜 AI처럼 느껴지는 지속형 companion이다. AI 같은 인상을 만드는 주요 원인으로 장문 답변, 즉답, 모든 메시지에 대한 반응, 지나친 친절과 질문, 대화 사이의 기억 단절을 가정한다.

원문이 제안한 경험의 축은 다음과 같다.

- 짧은 응답과 필요시 여러 Discord 메시지로 나누는 전송
- 메시지 길이와 상태를 반영한 읽기·생각·타이핑 지연
- 최근 대화, 사용자 사실, 사건, 미래 일정으로 나뉜 기억
- 페르소나, 관계 상태, 캐릭터의 생활 상태 분리
- 빈도 상한과 quiet hours가 있는 선제 메시지
- 대화·기억을 개인 서버에 두고 로컬 LLM을 우선하는 운영

## 제안 구조와 단계

원문의 흐름은 `Discord 어댑터 → 대화 제어 → 응답 정책·컨텍스트 구성 → LLM → 메시지 계획 → 지연·분할 전송`이다. 별도 스케줄러가 미래 일정, 마지막 대화, 최근 선제 메시지 횟수, 캐릭터 상태를 보고 대화를 시작하는 확장도 제안한다.

단계 구분은 다음과 같다.

1. MVP: Discord 대화, 로컬 모델, 페르소나, 최근 대화 지속성, 짧은 응답, 타이핑·지연, 메시지 분할
2. V2: 사용자 사실·사건·미래 일정 추출과 기억의 수정·삭제·충돌 해결
3. V3: 선제 메시지, 기분·에너지, 관계 상태, 가상 일상, 선택적 응답
4. V4: 이미지, 음성, 아바타 등 멀티모달

평가 후보는 평균 메시지 길이와 턴당 메시지 수, 장문·과도한 질문·페르소나 위반·잘못된 기억·반복 패턴의 발생, 기억 회수 정확도, 선제 메시지 응답률, 사용 후 자연스러움이다. 아직 측정 결과나 합격 기준은 아니다.

## 현재 로컬 설계와의 관계

| 항목 | Notion 초기 제안 | 현재 구현·설계 기준 |
| --- | --- | --- |
| 로컬 모델 연결 | Ollama | 사용자 결정에 따라 LM Studio를 첫 어댑터로 사용 |
| 첫 대화 경험 | 분할·지연까지 MVP에 포함 | 짧은 단일 응답과 처리 중 표시를 먼저 검증하고 분할·지연은 비교 실험 뒤 결정 |
| 기억 | 최근 20~30개 메시지와 자동 추출 계층 | 최근 대화 상한과 예산을 적용하고 수동 사실 CRUD·삭제 일관성을 먼저 구현 |
| 운영 화면 | 구체 범위가 작음 | 페르소나·사실·대화의 조회·수정·삭제와 revision 확인을 최소 MVP에 포함 |
| 장기 기능 | 관계·생활 상태와 선제 메시지 | 필요성·안전 정책을 검증할 후속 범위로 유지 |

따라서 Notion은 제품 의도와 후보 아이디어의 출처이고, 로컬 문서는 현재 구현 계약과 우선순위의 원본이다. 둘이 다르면 로컬 결정 기록과 프로젝트 문서를 따른다.
